# QUALITY CHECKLIST — Criminal Story 品質検証

作成：2026-11-25（品質検証担当）
対象：試作版0.1（`game/index.html`、HTMLレイキャスター版）の酷評の分解と、
3D版（Godot 4／ストーリー主導／操作は限定的／冒頭は出産シーン）の合格基準。

使い方：

- 各項目は「合格条件（判定できる形）」「判定方法」「不合格の例」の3点セットで書く。
- 判定は必ず **実際に起動してプレイした結果** または **画面キャプチャ** で行う。
  コードを読んだだけ、ビルドが通っただけでは合格にしない。
- 優先度は P0＝今すぐ直すべき／P1＝町ができてから／P2＝Steam直前、の3段階。
  まとめは本書の最後（第4章）。

## 第1章 試作版0.1が酷評された理由の分解（コードによる裏付け）

ユーザーの評価は「おもんない／人が出てこない／まわりが粘土／意味が分からない／言葉もない」。
これは好みの問題ではなく、下記のとおり実装上の欠落としてコードから裏付けられる。

### 1-1. 人が一人も出てこない

- 根拠：描画は `draw()` のレイキャスティングのみ。画面に出るのは壁・天井・床・ミニマップだけ。
  人物・NPC・スプライト・会話のデータ構造も処理も存在しない（`CHAPTERS` にあるのは
  `year / title / place / height / wall / text` の6項目だけで、人物の項目がない）。
- 結果：母親、兄キース、ティリア・ムーアなど、物語の中心人物が文章の中にしかおらず、
  プレイヤーは誰にも会わないまま一生が終わる。「人生を再現する」ゲームの核が未実装。

### 1-2. 周囲が「粘土」（単色・質感なし・場所が分からない）

- 根拠1：全8章で **マップは1枚共通**（`MAP`、12×12）。章が変わっても部屋の形は同じで、
  変わるのは `wall` のRGB値1組だけ。病院・祖父母の家・ハイウェイ・バー・法廷・独房が
  すべて同じ間取り・同じ壁になる。
- 根拠2：壁は距離で暗くした単色の縦帯、天井は `#202028`、床は `#3a332a` のべた塗り固定。
  テクスチャ、模様、家具、窓、看板、車両などの物体は一切描かれない。
- 根拠3：場所の違いを示す情報は HUD の文字（章タイトル・年・地名）だけ。
  画面を見ただけでは「ここがどこか」を当てる手がかりがゼロ。
- 結果：「色の違う粘土の壁の迷路」と感じるのは正しい反応であり、描画方式の限界でもある。

### 1-3. 目的と物語が伝わらない（「意味が分からない」）

- 根拠1：全章の目的表示が **同一のテンプレート文**：
  「目的：部屋を一人称で進み、光る出口（E）までたどり着くこと。」
  章ごとの出来事に沿った目的は1つもない。
- 根拠2：物語は画面下の文章欄（`#story`）に表示されるだけで、世界の中の出来事と
  結びついていない。文章を読まなければ何の話か分からず、読んでも「歩く理由」にはならない。
- 根拠3：章の切り替えは、年と地名だけのオーバーレイ（「次の章へ」）で、
  前の章で何が起き、今なぜここにいるのかの接続がない。
- 根拠4：第6章（事件の時期）の文章自体が「ハイウェイを歩き抜け、時期の終わりへ進むだけである」
  と明記しており、最も重要な時期が「ただ歩く」設計になっている。
- 結果：プレイヤーの体験は「物語」ではなく「8回繰り返す出口探し」になる。

### 1-4. 操作だけが残り、操作自体も単調

- 根拠：入力は移動（WASD／矢印）と視点回転のみ。調べる、話す、選ぶ、拾う等の
  インタラクションは存在しない。出口判定も「Eセルに0.55以内へ近づく」だけ。
- 補足：ユーザーが後に示した方針は「操作できるところは限られていて、ストーリーが
  始まっていく」形。0.1は逆で、**ストーリー演出がなく操作（移動）だけが残った** ため、
  方針と正反対の出来になっていた。

### 1-5. その他の不足（副次的だが体験を下げる）

- 音が一切ない（効果音・環境音・音声・ミュート設定すべてなし）。
- セーブ／続きから再開がない。章選択もない（最初から歩き直しのみ）。
- 設定画面がない（感度・音量・字幕などの調整不可）。感度は `0.0025` 固定。
- ミニマップが常時表示され、出口の位置まで見えるため、探索の緊張感もない。
- 終了画面はお礼と「次は別の人物を追加予定」の告知のみで、
  人生をたどり終えた余韻や振り返り（年表・出典）がない。
- 視点の高さ（`height`）で赤ん坊〜大人を表現する工夫はあるが、効果は地平線が
  最大で約46ピクセルずれる程度で、体験の差としてはほぼ伝わらない。

### 1-6. できていた点（作り直しでも維持すること）

- 事実関係は `docs/RESEARCH.md` の出典（Britannica中心）と対応しており、
  年号・場所・人数に推測の混入がない。
- 本人の主張（正当防衛）と裁判結果（6件で死刑判決）を併記し、断定を避けている。
- 犯罪の手口・残虐描写を扱わない方針が明記され、本文でも守られている。
- 単一HTMLファイルで接続不要・即起動できる手軽さ（製品版では不要だが試作としては利点）。

## 第2章 3D版の合格基準（Godot 4／ストーリー主導）

前提となる確定仕様（ユーザー指示）：

- 土台は Godot 4 の本物の3D。レイキャスター方式は使わない。
- グラフィックと町の様子を可能な限り上げる（建物・道路・車・人・光と影のある町）。
- 操作は限定的。ストーリーが主導で進み、プレイヤーは合間に短く歩く／見回す／
  近づいてボタンを押す程度。進む先は1つに絞り、迷わせない。
- 冒頭は「赤ちゃん期」ではなく **生まれてくる場面そのもの**（病院、1956-02-29、
  ミシガン州ロチェスター）から始まる。
- 1人目（Aileen Wuornos）を十分な質にしてから人数を増やす。

### A. 冒頭30秒（最重要）

- [ ] **A1 30秒で物語が分かる**（P0）
  - 合格条件：起動後30秒以内に、画面上の情報だけで「いま何年・どこで・誰の・
    どんな物語か」が分かる表示がある（例：年号・場所の字幕＋場面そのもの）。
  - 判定方法：事情を知らない人に冒頭30秒だけ見せ、「何の話だと思うか」を聞く。
    「1956年、アメリカの病院で、ある女性が生まれる場面」と趣旨が伝われば合格。
  - 不合格例：タイトル画面と操作説明だけで30秒が終わる／文章を読まないと分からない。
- [ ] **A2 冒頭の最初の場面に人がいる**（P0）
  - 合格条件：出産シーンの最初のカットに、医師・看護師・母親のうち2人以上が
    人物として画面内に存在し、誰が誰か（役割）が見た目・名札・セリフで判別できる。
  - 判定方法：冒頭の画面キャプチャ1枚で判定する。人物が「棒人間・色付きの箱」
    レベルなら不合格。
  - 不合格例：無人の病室／声だけで姿がない／全員同じ見た目で役割不明。
- [ ] **A3 生まれた瞬間が演出で伝わる**（P0）
  - 合格条件：視界の変化（ぼやけ→開ける等）、周囲のセリフ、音のいずれか2つ以上で
    「生まれた」という出来事が、文章の説明なしでも伝わる。
  - 判定方法：字幕・文章欄を隠した状態で冒頭を再生し、出来事を言い当てられるか。
  - 不合格例：気づいたら病室に立っている／出産の描写が生々しい医療描写になっている
    （方針違反としても不合格）。
- [ ] **A4 冒頭で操作に迷わない**（P0）
  - 合格条件：冒頭はほぼ見るだけ（視点を少し動かせる程度）で自動で進み、
    プレイヤーが何もできずに30秒以上止まる場面がない。
  - 判定方法：キーボード・マウスに触らず放置し、物語が先へ進むことを確認する。

### B. 人物（NPC）

- [ ] **B1 各章に、その章の関係者が登場する**（P0）
  - 合格条件：全章で最低1人、物語上重要な章では2人以上の人物が3D空間に登場する。
    章と人物の対応表（誰が・どの章に・何の役割で出るか）がdocsに存在する。
  - 判定方法：対応表と実プレイを突き合わせる。文章だけに名前が出て姿がない人物は
    「未登場」として数える。
- [ ] **B2 人物に近づくと名前とセリフが表示される**（P0）
  - 合格条件：対象人物に近づく／ボタンを押すと、名前＋その場面に合った短いセリフが
    表示され、セリフは事実関係と矛盾しない（創作セリフは「演出」として
    事実の断定と混ざらない書き方にする）。
  - 判定方法：各章の全人物で実際に話しかけ、表示を確認する。
- [ ] **B3 人が「置物」になっていない**（P1）
  - 合格条件：主要人物は最低限の動き（向きを変える、歩く、座る等）があり、
    プレイヤーと無関係に固まっていない。通行人にも歩行などの生活動作がある。
  - 判定方法：町と病室で各1分間観察し、動いている人物がいることを確認する。

### C. 町と環境（「粘土」の解消）

- [ ] **C1 場所が画面だけで判別できる**（P0）
  - 合格条件：病院・住宅街・バー・法廷・刑務所など主要な場所について、
    HUDの文字を隠した画面キャプチャで、第三者が場所の種類を言い当てられる。
  - 判定方法：各場所のキャプチャを文字なしで見せて判定する。
    家具・設備（病室のベッドと医療機器、バーのカウンター、独房のベッド等）が
    場所の根拠になっていること。
- [ ] **C2 壁・床・天井が単色べた塗りでない**（P0）
  - 合格条件：主要な場所すべてで、材質の違い（木・タイル・コンクリート・芝生等）が
    テクスチャまたは陰影で判別できる。単色マテリアルだけの面が画面の大半を
    占める場所がない。
  - 判定方法：各場所のキャプチャを目視する。「粘土」と言われる見た目なら不合格。
- [ ] **C3 町に生活感がある**（P1）
  - 合格条件：町の区画に次の要素が揃う：住宅と店舗の区別、道路と歩道、車両
    （駐車・走行のいずれか）、街灯・信号・看板等の生活設備、歩行者、
    時間帯に応じた光（太陽光と影）。要素ごとに有無をチェックし、
    6項目中5項目以上で合格。
  - 判定方法：町を一人称で1周歩き（またはカメラで一周し）、項目を数える。
- [ ] **C4 章ごとに場所の作りが違う**（P1）
  - 合格条件：章の舞台が変われば、間取り・置かれた物・光の雰囲気のうち
    2つ以上が変わる。0.1のような「色だけ変更」は不合格。
  - 判定方法：全章のキャプチャを並べて比較する。

### D. 物語と目的（ストーリー主導）

- [ ] **D1 章ごとに目的が1つに絞られている**（P0）
  - 合格条件：各章でプレイヤーがやることは1つだけ（例：「母親のそばへ行く」
    「○○に話しかける」）で、画面上に常時1文で表示され、達成すると自動で
    次の場面へ進む。目的が2つ以上同時に出ない。
  - 判定方法：全章をプレイし、目的表示と実際の達成条件が一致するか確認する。
- [ ] **D2 章の接続で「なぜ今ここにいるか」が分かる**（P0）
  - 合格条件：各章の冒頭に、前章からのつながりを示す導入（年号・場所・
    何が起きたかの1〜2文）が場面と一緒に提示され、章の終わりには
    その章の出来事のまとめがある。
  - 判定方法：途中の章から始めても、前後関係の説明があることを確認する。
- [ ] **D3 操作の自由度が「限定的」の範囲に収まっている**（P0）
  - 合格条件：操作場面でも行き先は実質1つで、関係ない場所へ行って
    詰まる・迷うことがない。無操作でも物語が止まり続ける場面は、
    目的表示がある場合を除き作らない。
  - 判定方法：わざと逆方向へ進む・放置する等の「迷子テスト」を行い、
    進行不能にならないことを確認する。
- [ ] **D4 最期まで到達でき、終わりが「終わり」として伝わる**（P0）
  - 合格条件：最終章（2002年、死刑執行）まで詰まらず到達でき、終了時に
    人生の振り返り（年表）と出典への案内が表示される。
    「次は別の人物を追加予定」のような開発告知で終わらない。
  - 判定方法：通しプレイでエンディング画面まで到達し、表示内容を確認する。

### E. 事実と出典

- [ ] **E1 ゲーム内の全ての事実が `docs/RESEARCH.md` に対応する**（P0）
  - 合格条件：年号・日付・場所・人数・固有名詞について、ゲーム内テキストと
    RESEARCH.md を全量照合し、出典のない事実が0件。
    新しい事実を足す場合は、先にRESEARCH.mdへ出典付きで追記する手順を守る。
  - 判定方法：テキストを書き出して1件ずつ照合する（サンプル確認で済ませない）。
- [ ] **E2 主張と確定事実が区別されている**（P0）
  - 合格条件：本人の主張（正当防衛など）は「本人の主張」として、
    裁判結果は「裁判の結果」として書き分けられ、一方だけが
    事実として断定されていない箇所が0件。
- [ ] **E3 手口・残虐描写がない**（P0）
  - 合格条件：凶器の使い方・殺害の手順・遺体の描写など、事件の手口や
    残虐な場面の描写が、本文・セリフ・演出のいずれにも0件。
    事件の時期の章も「起きた事実」までに留める。
- [ ] **E4 出典がプレイヤーから辿れる**（P1）
  - 合格条件：タイトル画面またはエンディングから、出典一覧（Britannica等）へ
    1〜2操作で辿れる。ストアページにも同じ出典方針が書かれている。

### F. 見た目・技術品質

- [ ] **F1 人物・建物が「何か」が分かる形をしている**（P0）
  - 合格条件：人物は頭・胴体・手足と衣服の区別があり、建物は窓・ドア・屋根等で
    種類が判別できる。色付きの直方体の組み合わせだけで作られた主要物がない。
  - 判定方法：町・病室のキャプチャで判定する（C1/C2と併せて実施）。
- [ ] **F2 光と影で立体感がある**（P1）
  - 合格条件：屋外は太陽光と影、屋内は照明による明暗があり、
    のっぺりした全面均一な明るさの場面がない。
- [ ] **F3 使用アセットのライセンスが記録されている**（P1）
  - 合格条件：外部アセット（モデル・テクスチャ・フォント・音楽）すべてについて、
    出どころ・ライセンス・商用利用可否がdocsに一覧化され、
    ライセンス不明の素材が0件。

### G. 音・UI・アクセシビリティ

- [ ] **G1 音がある、かつ消せる**（P1）
  - 合格条件：環境音または効果音が場面に付き、設定で音量調整とミュートができる。
    出産シーンの泣き声など、場面の理解を助ける音が最低1つある。
- [ ] **G2 字幕が常時読める**（P1）
  - 合格条件：セリフはすべて字幕表示され、文字サイズが設定で変更でき、
    明るい背景でも読める縁取り・背景がある。
- [ ] **G3 操作説明が画面内にある**（P1）
  - 合格条件：その場面で使える操作だけが画面に表示され、
    外部の説明書なしで最後まで進められる。

### H. 動作・安定性

- [ ] **H1 目標環境で最後まで止まらず動く**（P0）
  - 合格条件：想定する Windows PC で、起動→エンディングまで通しプレイでき、
    クラッシュ・無限ロード・進行不能が0件。フレームレートは
    町場面で常時30fps以上を目安とする（実測値を記録する）。
  - 判定方法：実機での通しプレイ記録（日時・環境・結果）をdocsに残す。
    開発環境（Linux VM）での確認だけで「合格」にしない。
- [ ] **H2 セーブと再開が正しく働く**（P1、第3章S3と連動）
  - 合格条件：章の区切りで自動保存され、再起動後に続きから再開できる。
    保存データが壊れた場合は最初から始められる案内が出る。

## 第3章 Steamで出す前に必要な品質・運用項目（主にP2）

### S. ストア・法務・表示

- [ ] **S1 年齢制限・コンテンツ表示が正しい**
  - Steamworks のコンテンツアンケートに正直に回答し、殺人・死刑・性風俗の仕事・
    未成年への虐待の言及など、本作に含まれる要素をもれなく申告する。
  - ストアページとゲーム内に、対象年齢の目安と内容の注意書きを表示する。
  - 判定：申告内容と実際のゲーム内容を第三者が照合し、食い違い0件。
- [ ] **S2 実在人物を扱う注意書きがある**
  - タイトル画面とストアページに明記する文面を用意する：
    本作は実在の人物・事件に基づく再現であること／犯罪を称賛・正当化する
    内容ではないこと／被害者とその遺族への配慮の方針／事実は公開資料に基づき、
    セリフ等の演出部分は創作を含むこと（事実と創作の区別の方針）。
  - 実在の存命人物（関係者を含む）の名誉・プライバシーに触れる表現がないか、
    公開前に全テキストを再点検する。
- [ ] **S3 権利関係の確認**
  - 映画『モンスター』（2003）など既存作品のタイトル・画像・音楽を無断使用していない。
  - 実在の店舗名・商標・ロゴの使用が最小限で、問題になるものは架空名へ置換済み。
  - 使用アセットのライセンス一覧（F3）がストア公開時点の内容と一致している。

### T. 製品としての完成度

- [ ] **T1 セーブ機能**：章区切りの自動保存＋タイトル画面からの続き／最初から／
  章選択（クリア済み章）の3導線がある。
- [ ] **T2 設定画面**：音量（BGM／効果音／音声の個別調整とミュート）、
  画面（解像度・フルスクリーン／ウィンドウ・明るさ）、
  操作（マウス感度・視点反転・キー割り当ての確認）、
  字幕（表示／サイズ）が変更でき、再起動後も保持される。
- [ ] **T3 動作環境の確認と公表**：最低・推奨スペックを実機テストで決め、
  ストアページの表記と一致させる。低スペック向けの画質設定
